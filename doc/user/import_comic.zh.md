# 本地漫画导入

英文版本：[import_comic.en.md](import_comic.en.md)

## 简介

VeneraNext 支持从本地目录、漫画压缩包、PDF 和图片型 EPUB 导入漫画。导入后的内容会统一存放为本地图片漫画，以复用现有阅读模式、进度记录和拆分双页等能力。

支持的漫画图片扩展名包括 `jpg`、`jpeg`、`jpe`、`png`、`webp`、`gif` 和 `avif`。

## 恢复本地下载

如果迁移应用时保留了本地下载文件夹，但丢失了 `local.db`，可以通过扫描当前本地路径恢复本地数据库。

- 打开 `本地` -> `导入` -> `恢复本地下载`。
- 应用会扫描当前本地存储路径并重建条目。
- 该操作不会复制文件，也不会添加收藏。
- 同名标题或目录会被视为重复并跳过。

执行前请确认设置中的本地存储路径指向包含已下载漫画的目录。

## 漫画目录

目录只有符合以下两种结构之一时，才会被视为漫画目录。

**无章节目录**

```text
comic_directory
├── cover.[ext]
├── img1.[ext]
├── img2.[ext]
├── img3.[ext]
├── ...
```

**包含章节目录**

```text
comic_directory
├── cover.[ext]
├── chapter1
│   ├── img1.[ext]
│   ├── img2.[ext]
│   ├── img3.[ext]
│   ├── ...
├── chapter2
│   ├── img1.[ext]
│   ├── img2.[ext]
│   ├── img3.[ext]
│   ├── ...
├── ...
```

图片文件名可以任意命名，但扩展名必须是有效图片格式。

页面顺序由文件名决定。应用会按文件名排序后按顺序显示。

封面图是可选的。如果目录中存在 `cover.[ext]`，它会被识别为封面；否则第一张图片会被用作封面。

漫画标题使用漫画目录名。章节标题使用章节目录名。

## 压缩包

VeneraNext 支持从压缩包导入漫画。

压缩包适合作为导入、导出、归档、迁移和分发格式，应符合 [Comic Book Archive](https://en.wikipedia.org/wiki/Comic_book_archive_file) 格式。

当前支持以下压缩包格式：

- `.cbz`
- `.cb7`
- `.zip`
- `.7z`

压缩包可以直接包含图片，也可以包含一个顶层目录；如果顶层目录下是多个章节目录，应用会按章节目录导入。

```text
猫之眼[北条司].cbz
└── 猫之眼[北条司]
    ├── cover.jpg
    ├── 第01卷
    │   ├── 001.jpg
    │   └── 002.jpg
    └── 第02卷
        ├── 001.jpg
        └── 002.jpg
```

如果根目录没有 `cover.[ext]`，应用会使用第一章的第一张图片作为封面。

## PDF 与图片型 EPUB

在 `本地` -> `导入` 中可以分别选择 PDF 漫画文件或图片型 EPUB 文件。这两种格式都会在导入时转换为应用管理的本地图片漫画，而不是直接读取原文件。

### PDF

- 每个 PDF 页面会按顺序渲染为 JPEG 图片，第一页同时作为封面。
- 导入结果是无章节的单本漫画，标题默认使用 PDF 文件名。
- 为兼顾清晰度、内存和存储占用，页面按约 3 倍 PDF 点尺寸渲染，最长边限制为 3000 像素。
- 加密或需要密码的 PDF 暂不支持。
- 导入会生成新的图片副本，因此需要预留额外本地存储空间。

### 图片型 EPUB

- 支持 spine 中直接引用栅格图片，或 XHTML/SVG 页面通过 `img`、SVG `image` 引用栅格图片的固定版式 EPUB。
- 页面顺序以 EPUB spine 为准；元数据中的标题、作者和封面会尽量保留。
- 当 EPUB 导航中存在多个有效章节时会保留章节；没有明确章节导航时会导入为无章节漫画。
- 原始栅格图片会直接复制，不重新压缩。
- 文字型 EPUB、直接绘制的 SVG 页面、外部图片引用和越界路径会被拒绝，不会静默丢弃正文。

当前不支持 MOBI、AZW 和 AZW3。它们是电子书容器而不是本项目当前的图片漫画交换格式，建议先在外部工具中转换为图片型 EPUB、PDF 或 CBZ。

如果本地漫画库中已经存在同名作品，文档导入不会覆盖原内容。

## WebDAV 在线漫画库

WebDAV 漫画库是在线阅读渠道，和本地导入导出、WebDAV CBZ 归档是不同能力。

在线阅读只读取远端目录图片，应用会按需列目录和加载图片，不会把远端 CBZ/ZIP/7Z 当作在线预览内容。可以直接使用普通图片目录，也可以把 VeneraNext 导出的单本 CBZ 解压后放到 WebDAV，以保留标题、作者、标签和章节信息。

“WebDAV 漫画库”设置中的“同步漫画库配置”开关默认关闭。启用后，DataSync/Appdata 的 `.venera` 数据会包含漫画库地址、用户名、密码、远程路径、自动更新开关和更新间隔；接收设备也必须在本地启用该开关才会导入这些字段。凭据会存储在远程 `.venera` 文件中，只应在可信的 WebDAV 和账号上启用。

### 普通目录模式

推荐结构：

```text
/venera_comics/
└── 猫之眼[北条司]
    ├── cover.jpg
    ├── 第01卷
    │   ├── 001.jpg
    │   └── 002.jpg
    └── 第02卷
        ├── 001.jpg
        └── 002.jpg
```

普通目录模式的规则：

- 漫画标题取漫画文件夹名。
- 子目录作为章节；如果根目录直接包含图片，则根目录图片可作为单章节漫画阅读。
- 页面和章节按文件名排序，推荐使用补零编号，例如 `0001.jpg`、`0002.jpg`。
- 封面优先使用根目录下文件名为 `cover` 的图片；支持 `jpg`、`jpeg`、`png`、`webp`、`gif`、`jpe`、`avif`。没有独立封面时，依次使用根目录首图、首个可读章节的 `cover.*` 或首图。
- 不要求 `metadata.json` 或 `ComicInfo.xml`。

### Bangumi 自动刮削

连接 Bangumi 后，同步 WebDAV 漫画库时会为缺少 `metadata.json` 的漫画自动搜索条目。搜索前会清理文件夹名末尾的 `作者：[北条司]`、`著者：【北条司】` 等明确标注的作者提示，以及 `语言：[Chinese]`、`版本[无修正]`、`[DL版]` 和 `汉化者：[汉化名]` 等已知发布注记；没有标签的未知括号内容会作为作品名保留。清理后的标题必须与 Bangumi 中文名或原名精确匹配；存在多个同名条目时，作者提示必须唯一匹配条目信息框或人物接口中的作者、原作、作画等创作关系。模糊或有歧义的结果不会写入。

匹配成功后，应用以仅新建的条件请求写入 UTF-8 `metadata.json`，不会覆盖同步期间由其他客户端创建的文件。标题优先使用 Bangumi `name_cn`，为空时使用 `name`；简介使用条目详情的 `summary`；作者来自条目信息框或人物接口；标签由全部官方 `meta_tags` 与按 `count` 降序排列的前 10 个用户标签合并去重。WebDAV 账号必须拥有漫画目录写权限。自动刮削不会覆盖任何已经存在的 `metadata.json`，也不会下载 Bangumi 封面。未匹配、失败和下次重试时间会随漫画缓存保存；刮削规则版本变化、达到重试时间或强制同步时会按状态重试。

用户在漫画详情页手动绑定 Bangumi 条目时，该条目被视为明确选择。`metadata.json` 中已有的 `bangumiSubjectId` 会在绑定面板中预选对应条目，但不会自动创建 Bangumi 收藏或绑定。绑定完成后会立即结束前台加载，应用再在后台读取条目详情并更新 WebDAV 漫画的 `title`、`author`、`description`、`tags` 和 `bangumiSubjectId`；即使新值为空，也会清除旧的错误字段。写入前会读取最新版元数据，以 ETag 或 Last-Modified 条件更新，并在并发冲突后重新合并；合法的 `chapters` 页码范围和未知扩展字段会保留。服务器不给现有文件提供任一校验器时，应用会拒绝不安全的覆盖。临时失败会连同漫画库、漫画和条目身份保存在本地队列中，并在启动或退避时间到达后重试；如果配置或绑定已变化，旧任务不会写入新漫画库。后台写入失败不会撤销已经成功的进度绑定。

Bangumi 绑定按漫画库身份隔离；身份由规范化的服务地址、用户名和远程根路径组成，不包含密码，因此只更新密码不会丢失绑定，而切换服务器、账号或根路径不会复用旧库中同路径漫画的绑定。将状态改为“读过”时，应用会重新读取远端收藏与条目总话数/总卷数，一次提交两个进度维度；远端已有的更高进度和用户明确输入的更高值都不会被降低。

### 元数据标记的分层目录模式

如果 WebDAV 目录层级较深，建议在漫画根目录放置 `metadata.json`，将该文件夹明确标记为一本漫画：

```text
/venera_comics/
└── 分类/
    └── 作者/
        └── 猫之眼/
            ├── metadata.json
            ├── cover.jpg
            ├── 第01章/
            │   ├── 001.jpg
            │   └── 002.jpg
            └── 第02章/
                └── 001.jpg
```

应用会在同步 WebDAV 漫画库时递归查找带有 `metadata.json` 的目录，并将该目录作为一本漫画；其直接子目录作为章节。找到漫画根目录后不会继续把章节或更深层目录单独识别为漫画。漫画 ID 使用相对于 WebDAV 漫画库路径的目录路径，因此不同分类下的同名漫画不会互相覆盖。

在这种模式下，漫画标题、作者、简介和标签来自 `metadata.json`，章节名称和章节路径来自直接子目录。根目录下的 `cover.*` 只作为封面；如果根目录还有普通图片，它们会作为 `Images` 章节保留。

当目录同时存在真实章节文件夹和 `metadata.json` 中的 `chapters` 页码范围时，真实章节文件夹优先，页码范围不会被强行映射到文件夹。只有根目录图片、没有章节文件夹时，`chapters[].start` 和 `chapters[].end` 才用于扁平 CBZ 目录的虚拟分章。

同步会在受限深度和目录数量内递归发现未标记的多层漫画：包含普通根目录图片的目录会直接视为漫画；直接子目录全部使用“第 01 话”“Volume 2”等章节式名称时，其父目录会视为漫画。包含 `metadata.json` 的目录仍是最明确的边界。对于名称无法判断的复杂层级，建议在漫画根目录补充 `metadata.json`，避免分类目录或章节被误识别。

### CBZ 解压增强模式

VeneraNext 导出的单本 CBZ 解压后通常是扁平图片目录：

```text
/venera_comics/
└── 猫之眼
    ├── metadata.json
    ├── ComicInfo.xml
    ├── cover.jpg
    ├── 0001.jpg
    ├── 0002.jpg
    ├── 0003.jpg
    └── 0004.jpg
```

`metadata.json` 模板：

```json
{
  "title": "猫之眼",
  "author": "北条司",
  "description": "三姐妹经营咖啡店并寻找父亲失踪真相的故事。",
  "tags": ["动作", "漫画"],
  "chapters": [
    {"title": "第01卷", "start": 1, "end": 2},
    {"title": "第02卷", "start": 3, "end": 4}
  ],
  "bangumiSubjectId": 123456
}
```

字段规则：

| 字段 | 类型 | 说明 |
|---|---|---|
| `title` | 字符串 | 漫画标题；空字符串会回退为文件夹名 |
| `author` | 字符串 | 作者，可为空字符串 |
| `description` | 字符串 | 漫画简介，可为空字符串；Bangumi 刮削时来自条目详情的 `summary` |
| `tags` | 字符串数组 | 漫画标签，可为空数组 |
| `bangumiSubjectId` | 正整数或 `null` | 对应的 Bangumi Subject ID；自动刮削或手动绑定时写入 |
| `chapters` | 数组或 `null` | 章节范围；为 `null` 或空数组时，根目录图片作为单章节 |
| `chapters[].title` | 字符串 | 章节显示名称，不可为空 |
| `chapters[].start` | 整数 | 章节起始页，从 1 开始，包含该页 |
| `chapters[].end` | 整数 | 章节结束页，包含该页 |

章节范围必须按顺序排列、不得重叠、不得反向，并且不能超过根目录实际页面数。`cover.*` 不计入页面编号。元数据允许存在额外字段，以便后续扩展；当前不会从元数据读取远端 URL、脚本或本地绝对路径。

`metadata.json` 使用 UTF-8 编码，文件名匹配不区分大小写。`ComicInfo.xml` 会随 CBZ 导出保留，用于其他漫画阅读器兼容；VeneraNext WebDAV 漫画库当前以 `metadata.json` 为增强信息来源。

如果元数据文件缺失，连接 Bangumi 后会先按上述保守规则尝试自动刮削；无法匹配时回退普通目录模式。如果文件已经存在但无法读取、JSON 损坏、字段类型错误或章节范围不合法，自动刮削不会覆盖该文件，漫画仍会按可解析内容或普通目录模式显示。用户明确绑定 Bangumi 条目后，若文件仍是可解析的 JSON 对象，条件合并可以修复标题、作者、简介和标签，并尽量保留结构合法的 `chapters`；无法解析的文件不会被静默替换。

这里的 `metadata.json` 是单本 CBZ 的元数据格式，不是 `.venera-comics` 批量导出包中的漫画列表格式，两者不可混用。

### 压缩包与在线阅读

CBZ/ZIP/7Z 仍然可以通过 WebDAV 归档功能上传、下载和恢复，但它们属于备份与分发格式，不用于在线阅读。需要在线阅读时，请先在 WebDAV 服务端解压；应用只按需读取解压目录中的图片，不会下载整个压缩包。
